## Where the port is

LEGO Star Wars: The Complete Saga (Xbox 360) is statically recompiled with XenonRecomp and runs on Windows with a D3D12 back end.
The full title screen now renders correctly on the GPU at about 60 fps:

- LEGO Star Wars logo
- starfield
- Anakin / Darth Maul character banner
- textured ships with glowing lasers

The renderer uses the game's real shaders, translated with Xenia's `DxbcShaderTranslator`.

### Launch

From the project root (Git Bash):

```
./run.sh build
EXTRA="LSWTCS_PRISTINE=1 LSWTCS_FPS_CAP=60 LSWTCS_HEAPBYPASS=0 LSWTCS_GAMEROOT=X:/none/" ./run.sh run 15
```

- The title screen appears after about 1.5–2 minutes.
- About 1 in 3 boots hangs during load (`[EB58] enter` without `[EB58] RETURN` in `LSWTCSRuntime/build/trace.log`). If that happens, just relaunch.
- Logs: `LSWTCSRuntime/build/trace.log` (`dbg_ram`) and `LSWTCSRuntime/build/run_out.txt` (`printf`).
- Screenshots: add `LSWTCS_SHOTS=N` to save one PNG every N frames to `build/shots/`. This is slow, so don't use it in load-timing tests.
- Add `LSWTCS_NORDOC=1` when you need crash diagnosis. Otherwise RenderDoc's crash handler swallows crashes.
- To catch a crash, run the exe under `cdb -g -G` with the env from `run.sh`.

## Current frontier: the game advances past the title, but no menu ever draws

The user pressed A (Space) at the title. The logo and banner disappear, and the starfield fly-by keeps running.

What has been verified:

- **Rendering is not losing anything.**
  - `[GPUMISS]` census: every draw reaches the GPU path.
  - `[FRAMEDIAG]`: the only offscreen draw dropped is a depth-clear quad (surface `0x0A020280`).
  - `[TEXFMT]`: every texture format is supported.
  - The main thread is in the normal render loop (`VdSwap`), not in a wait.
- **System calls after A, in order:**
  1. `XamShowDeviceSelectorUI` (completed, device 1)
  2. `XamContentCreateEnumerator` and `XamEnumerate`: fixed this session, now return a valid handle and NO_MORE_FILES
  3. `XMsgStartIORequest app=0xFB msg=0x000B0006 buf len=24`
  4. `XamEnumerate` on handle `0x3EE13C8F`: garbage, because our `XMsgStartIORequest` stub never fills the buffer with an enumerator handle
  5. The game then polls `XNotifyGetNext` and `XamUserGetSigninState` forever.

Strongest leads, check the first one first:

1. **XN_SYS_UI notification never sent.** On real hardware and Xenia, showing system UI such as the device selector posts XN_SYS_UI (id 0x9) with param 1 when the UI opens and param 0 when it closes. Our `XNotifyGetNext` only delivers the two boot notifications. The game probably waits for "UI closed" before showing the menu. Compare with Xenia's `xam_ui.cc` and `xam_notify.cc`, then queue `XN_SYS_UI` 1 → 0 around `XamShowDeviceSelectorUI` and the other `XamShow*UI` stubs.
2. **XMsg 0x000B0006 needs a real reply.** Find what XAM message this is in Xenia's `xam_msg.cc` / `xam_user.cc` (likely an enumerator creation), and write a valid enumerator handle into the request buffer.
3. **The save flow may need content creation.** `XamContentCreateEx` is still a no-op, and there is no `save:` device mapping. Implement it like Xenia's content manager, with a host folder.

Compare against the Xenia source in `xenia-canary/src/xenia/kernel/xam/`.

## What this session built (all in `LSWTCSRuntime/`)

### Earlier pieces still in place (memory sections 9–14)

- Physical-memory aliasing: 0x80, 0xA0 and 0xC0000000 are views of one 512 MB section, and the dispatch table moved to `0x100000000`.
- Exact ring walk up to the real write pointer.
- Predicated tiling disabled (NODEFER).
- Critical sections never return unlocked.
- D3D worker gates (WAITINF, OWNGATE).
- `mftb` reports real time at 49.875 MHz.
- `KeQueryPerformanceFrequency` returns its value in r3.
- Ring size fixed.

### The GPU path (memory sections 15–16)

- **Translator library:** `xenos_dxbc/`, built as the `XenosDxbc` library (Xenia's translator plus small stubs).
- **Bridge:** `xenos_dxbc/lsw_gpu_bridge.cc` (`lsw_gpu_prepare`).
- **Texture decoder:** `xenos_dxbc/lsw_gpu_texture.cc`. CPU untiling, block-compressed formats kept compressed, mip chains, and samplers.
- **Geometry shaders:** `xenos_dxbc/lsw_gpu_gs.cc`, Xenia's geometry-shader generator extracted verbatim. Covers rectangle lists, quad lists and point sprites.
- **Recording:** in `source/kernel_stubs.cpp` (`gpu_record_draw`), writing to `include/lsw_gpu_frame.h`.
- **Replay:** `source/gpu_xedraw.inc`, included by `gpu_d3d12.cpp`. Uses Xenia's bindful root signature, a 512 MB shared-memory buffer, a PSO cache and a texture cache.
- **Kill switches:** `LSWTCS_GPUDRAW=0`, `_NOGS=1`, `_NOMIPS=1`, `_NOTEX=1`.
- **CPU fallback:** `LSWTCS_XVS` stays on as the fallback path. The CPU interpreter is built with `-Dxe=lswxi` so its shim classes can't clash with the real Xenia classes.

## Remaining roadmap

1. **Menu after Start:** the frontier above.
2. **Intermittent load hang:** about 1 in 3 boots, existed before this session.
3. **EDRAM render targets / resolves:** render-to-texture. Not needed yet; only one offscreen depth-clear draw exists today.
4. **3D/1D textures and MSAA.**
5. **Audio streams:** music `.xma` files fail to open because `GAMEROOT=X:/none/` is set deliberately, and XMA decoding is not implemented.
6. **Long term:** Switch build with real multithreading; the cooperative GIL is temporary.

## Working rules this user expects

- **Never kill a running game without asking.** The user often has it open. Ask "may I take the game for a run?" and wait.
- **Back up before every risky change** (`./backup.sh <label>`), and report after each "rabbit hole" is finished.
- **Use the three-agent pattern at roadblocks:** three subagents on different angles (one of them a skeptic) that must converge on one fix.
- **Never "fake an old CPU's speed".** Timing must follow real time, independent of the host CPU.
- **Write patch scripts to files.** Bash heredocs mangle `\n` and quotes, so write Python patch scripts to the scratchpad with the Write tool and run them. Several source files use CRLF line endings, so match line endings in replacements.
- **Verify automated cleanups.** Brace-matched probe removal once deleted a `pm4_extract_ib` call and blanked the screen. After any automated cleanup, compare call counts against the backup.
